# MarketPulse Event Schema Specification

Version: `1.0.0` (`schema_version: 1`)

All messages flowing through the core event log conform to the canonical event envelope and typed payload schemas defined below. State across the entire platform (order books, OHLC bars, indicators, portfolio balances) is derived strictly from these events.

---

## 1. Canonical Envelope

Every event contains standard metadata fields:

| Field | Type | Description |
|---|---|---|
| `seq` | `int` | Monotonically increasing 64-bit integer, gapless per simulation session (starting at 1). |
| `ts_ns` | `int` | Simulation timestamp in integer nanoseconds from session epoch. |
| `symbol` | `str` | Asset ticker symbol (e.g., `"AAPL"`, `"BTCUSDT"`). |
| `type` | `str` | Event type identifier (e.g., `"ORDER_SUBMITTED"`, `"TRADE_EXECUTED"`). |
| `schema_version` | `int` | Schema version (currently `1`). |
| `payload` | `dict` | Typed payload containing event-specific attributes. |

---

## 2. Event Types & Payloads

### 2.1 Session Events

#### `SESSION_STARTED`
Emitted when a simulation or replay session begins.
```json
{
  "seq": 1,
  "ts_ns": 0,
  "symbol": "SYSTEM",
  "type": "SESSION_STARTED",
  "schema_version": 1,
  "payload": {
    "session_id": "sim_20260921_001",
    "seed": 42,
    "config_hash": "a1b2c3d4e5f6...",
    "symbols": ["AAPL", "NVDA"]
  }
}
```

#### `SESSION_ENDED`
Emitted when a simulation session terminates.
```json
{
  "seq": 10500,
  "ts_ns": 3600000000000,
  "symbol": "SYSTEM",
  "type": "SESSION_ENDED",
  "schema_version": 1,
  "payload": {
    "session_id": "sim_20260921_001",
    "reason": "COMPLETED",
    "total_events": 10499
  }
}
```

---

### 2.2 Order Flow Events

#### `ORDER_SUBMITTED`
Generated by an agent or user entering an order.
- `order_id`: Unique identifier string.
- `side`: `"BUY"` | `"SELL"`
- `order_type`: `"LIMIT"` | `"MARKET"`
- `price_ticks`: Integer ticks (required for `LIMIT`, `null` or `0` for `MARKET`).
- `qty`: Positive integer quantity of shares/contracts.
- `tif`: Time In Force — `"GTC"` (Good 'Til Cancel), `"IOC"` (Immediate Or Cancel), `"FOK"` (Fill Or Kill).

```json
{
  "seq": 2,
  "ts_ns": 1000000,
  "symbol": "AAPL",
  "type": "ORDER_SUBMITTED",
  "schema_version": 1,
  "payload": {
    "order_id": "ord_001",
    "side": "BUY",
    "order_type": "LIMIT",
    "price_ticks": 15025,
    "qty": 100,
    "tif": "GTC"
  }
}
```

#### `ORDER_ACCEPTED`
Emitted by the matching engine upon validating and queuing an order.
```json
{
  "seq": 3,
  "ts_ns": 1050000,
  "symbol": "AAPL",
  "type": "ORDER_ACCEPTED",
  "schema_version": 1,
  "payload": {
    "order_id": "ord_001"
  }
}
```

#### `ORDER_REJECTED`
Emitted if an order fails validation (e.g., negative quantity, invalid price, unknown symbol).
```json
{
  "seq": 4,
  "ts_ns": 1060000,
  "symbol": "AAPL",
  "type": "ORDER_REJECTED",
  "schema_version": 1,
  "payload": {
    "order_id": "ord_bad_01",
    "reason": "INVALID_PRICE_TICKS"
  }
}
```

#### `ORDER_CANCELED`
Emitted when an order is successfully canceled from the book.
```json
{
  "seq": 25,
  "ts_ns": 15000000,
  "symbol": "AAPL",
  "type": "ORDER_CANCELED",
  "schema_version": 1,
  "payload": {
    "order_id": "ord_001",
    "reason": "USER_REQUESTED"
  }
}
```

### 2.3 Execution & Market State Events

#### `TRADE_EXECUTED`
Emitted whenever an incoming aggressive order matches a resting passive order.
- `trade_id`: Unique trade identifier.
- `price_ticks`: Execution price (always the resting order's price).
- `qty`: Number of shares filled.
- `aggressor_side`: `"BUY"` | `"SELL"` (identifies who crossed the spread).
- `buy_order_id`: Buyer order ID.
- `sell_order_id`: Seller order ID.

```json
{
  "seq": 100,
  "ts_ns": 50000000,
  "symbol": "AAPL",
  "type": "TRADE_EXECUTED",
  "schema_version": 1,
  "payload": {
    "trade_id": "trd_001",
    "price_ticks": 15025,
    "qty": 50,
    "aggressor_side": "BUY",
    "buy_order_id": "ord_002",
    "sell_order_id": "ord_001"
  }
}
```

#### `BOOK_DELTA`
Emitted to inform downstream components of changes in aggregated depth at a price level.
- `side`: `"BUY"` | `"SELL"`
- `price_ticks`: Integer price level.
- `new_total_qty`: Total resting quantity at this level (`0` indicates level removal).

```json
{
  "seq": 101,
  "ts_ns": 50000100,
  "symbol": "AAPL",
  "type": "BOOK_DELTA",
  "schema_version": 1,
  "payload": {
    "side": "SELL",
    "price_ticks": 15025,
    "new_total_qty": 50
  }
}
```

### 2.4 Scenario & Market Control Events

#### `MARKET_EVENT`
Injected by the simulation coordinator to introduce exogenous shocks or structural changes.
- `kind`: `"EARNINGS_SHOCK"` | `"VOLATILITY_REGIME"` | `"HALT"` | `"RESUME"`
- `params`: Key-value configuration parameters.

```json
{
  "seq": 500,
  "ts_ns": 180000000000,
  "symbol": "AAPL",
  "type": "MARKET_EVENT",
  "schema_version": 1,
  "payload": {
    "kind": "VOLATILITY_REGIME",
    "params": {
      "regime": "HIGH",
      "volatility_multiplier": 2.5
    }
  }
}
```

---

## 3. Serialization Rules

1. **Deterministic Keys:** When converting to JSON, dictionaries are sorted to maintain reproducible serialization across all platforms.
2. **Immutable Instances:** Event objects in Python are frozen dataclasses with slots (`frozen=True`, `slots=True`).
3. **No Floats for Money:** Prices are strictly integer ticks. Conversions to currency decimals use:
   $$\text{price\_currency} = \text{price\_ticks} \times \text{tick\_size}$$
